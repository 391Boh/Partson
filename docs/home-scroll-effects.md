# Продуктивність головної

На головній немає паралаксу фото, фонів чи текстових панелей. `PageScrollMotion` пропускає маршрут `/`; спільний контролер додатково виключає `.home-static`, зокрема під час переходів між маршрутами. Інші сторінки зберігають власні ефекти.

Промоблок має сталу адаптивну висоту (див. [home-highlights.md](home-highlights.md)). Він не читає геометрію й не записує CSS-змінні під час прокручування. Декоративні масковані фони статичні.

`HomeDeferredStack` завантажує код і дані секції при наближенні на 800 px (без запасу на повільному з’єднанні чи збереженні даних). Початковий стан observer при scrollY=0 не запускає секції. Після завершення критичних ресурсів одна idle-черга готує лише найближчі модулі. Перший скрол активує їх без очікування window.load; подальші перетини активують решту. Немає двох паралельних черг таймерів, які раніше імпортували й монтували всі три модулі відразу після відкриття сторінки. Монтаж очікує повний CSS, має обмежену затримку під час жесту й інтервал між секціями. Розміри плейсхолдерів зберігаються.

Перевірки: `scripts/test-home-loading.mjs`, `scripts/test-home-scroll-performance.mjs`, `scripts/test-home-web-vitals.mjs`, `scripts/test-home-highlights.mjs`. Браузерні заміри в dev не замінюють production Core Web Vitals на реальних пристроях.

Локальна перевірка 2026-10-21 (Chrome, Next dev): до змін промоблок мав 14–15 різних висот протягом одного проходу скролом; глобальний контролер активував 8 шарів на 390 px та 14 на 1440 px. Після змін висота стала (360/280 px), активних паралакс-шарів немає. У повторній перевірці початкового завантаження LCP становив 376/288 ms, CLS — 0; підготовлено 1/2 найближчих модулі замість усіх трьох. Це діагностичні локальні значення, не гарантія production LCP чи FPS.

Ізольований прогін `test-home-web-vitals.mjs` пройшов усі ширини 360, 390, 640, 768, 1024, 1440 px: INP 80–152 ms, CLS 0–0.00134, геометрія слотів і футера стала. Перший прогін одночасно з іншими браузерними тестами дав INP 232 ms на 1024 px; в ізольованому повторі — 120 ms. Перевірки TypeScript, ESLint змінених компонентів, складання CSS, завантаження, скролу, API та каруселі пройшли. Production build і перевірка на фізичному телефоні не виконувалися.

Перевірка затримки взаємодій у production-коді 2026-10-21: окрема локальна збірка `.next-home-response` через `next build --webpack --experimental-build-mode compile` + `generate-env`, сервер на порту 3101. `scripts/test-home-response-performance.mjs` з Chrome, CPU ×4, ширини 390/1440 px: INP 160/136 ms. Сценарій: перше відкриття входу без попереднього hover-прогрівання, введення email, закриття Escape, пошук авто, категорії та виробника. Кожне введене значення перевіряється; поріг INP — 200 ms. Це лабораторна перевірка production JS/CSS з динамічним серверним рендером, не польова статистика й не повна ISR-збірка. Повний `next build` успішно скомпілював код, але завершився помилкою статичної генерації `/blog/[slug]` через 8-секундний тайм-аут запиту до бази. Значення користувача 490 ms без назви метрики й умов вимірювання в цьому сценарії не відтворилося.


Стабільність завантаження: мобільна висота блогу тепер 380 px для резервного, статичного й карусельного режимів. У hero персональні дані займають зарезервовану область 180 px; заголовок, підпис і кнопки мають однакову геометрію до авторизації й після неї. Збережені авто/VIN/доставка прокручуються всередині цієї області. Перенесення довгого імені та зміна тексту переваг не збільшують рядки. `test-home-auth-layout.mjs` перевіряє однакові висоту панелі, координату кнопок і початок наступного блоку для очікування, гостя, авторизованого користувача й відкладеного довгого профілю (320, 390, 768, 1024, 1440 px). Початковий CLS на 1024 px зменшився з 0.0013345 до 0 у повторній перевірці. Паралельний повний `test-home-web-vitals.mjs` зупинився на порозі INP (368 ms на 360 px), при цьому CLS був 0; це не проходження загального тесту продуктивності.

Компактне оформлення профілю: зарезервовану область зменшено зі 180 до 144 px, заголовок профілю став однорядковим (20 px) без декоративної лінії; кнопки залишили область натискання 44 px. Зменшено проміжки між секціями та записами. Місця для персональних даних усередині стало більше завдяки зменшенню заголовка; довгі списки зберігають прокручування. Повні назви авто збережені у тексті й `title`. Перевірка геометрії всіх станів залишається `test-home-auth-layout.mjs`.
