# Спочатку товари з ціною

Звичайний перегляд каталогу без текстового пошуку та явного сортування спочатку показує товари з додатною ціною продажу, потім — решту. Товари лише із закупівельною ціною належать до другої частини. Явне сортування за назвою чи ціною та пошук зберігають власний порядок.

Сервер використовує фільтр 1С `ТолькоСЦеной`, повторно перевіряє наявність саме ціни продажу та читає вікна по 500 рядків. Курсор `pf1:` зберігає частину вибірки, код початку вікна та число вже показаних відповідних рядків. Це дозволяє повторно використовувати вікно без втрат і повторів, навіть коли перед товарами з ціною є багато рядків лише із закупівельною ціною.

Перше вікно невелике (удвічі більше за сторінку, щонайменше 48 рядків): 1С віддає його за ~0,3 с замість ~0,7 с для 500 рядків. Розмір вікна зберігається в полі курсора `w`; старі курсори без нього вважаються вікнами по 500. Відфільтрований список (виробник, група, пошук), у якому не більше 500 товарів, читається одним звичайним запитом і ділиться на сайті (`a` у курсорі): поточна 1С обробляє `ТолькоСЦеной` разом із фільтром у кілька разів повільніше.

Якщо 1С відповідає `price_filter: "sale_v1"`, частина без ціни читається з фільтром `ТолькоБезЦены` (`f` у курсорі), а пряма сторінка відкривається одним-двома запитами `ПрямаяСтраница` з `ТолькоСЦеной` / `ТолькоБезЦены`. Стара 1С цих полів не знає; тоді сайт пропускає вікна, як раніше, і 10 хвилин не перепитує пряму сторінку. Зміни 1С описано в `docs/1c/price-filters-and-page-stock.md`.

Для кінцевої послідовності без ціни (без `ТолькоБезЦены`) читається звичайний каталог. Порожня проміжна відповідь повторно перевіряється без кешу; курсор, який не просувається, спричиняє помилку. Помилка основного джерела не підміняє результат старою несортованою сторінкою. Версію браузерного кешу оновлено до `v52-priced-first`.

```sh
node scripts/test-catalog-priced-first.mjs
node scripts/test-direct-catalog-server.mjs
node scripts/test-catalog-name-sort.mjs
```
