# Головна: оптимізація початкового завантаження — 27.10.2026

Локальні зміни, без публікації. Вихідні 1868/2070/2071 мс користувача не відтворені в ідентичних умовах, тому їх не порівнюємо напряму з локальними цифрами. Контрольний HTTP-запит до https://partson.shop дав TTFB приблизно 306–384 мс; один браузерний прохід — 375 мс / DOMContentLoaded 1391 мс. Це не польова статистика.

## Що виправлено

- Усунуто автоматичне передзавантаження повного CSS. React обробляв JSX-посилання на стилі в резервних noscript/404 як ресурси для preload навіть під час успішного відкриття головної. Noscript тепер містить звичайний HTML, а 404 — локальний CSS @import, який працює лише при відображенні 404. Повний CSS залишається доступним без JavaScript.
- На головній повний CSS запускається після DOMContentLoaded з низьким пріоритетом. Критичний CSS залишається блокуючим і оформлює перший екран; відкладені компоненти продовжують чекати готовності повного CSS. Інші маршрути зберігають попередній час запуску стилів. Загальний обсяг CSS не зменшився: приблизно 178 КБ мережевого трафіку перенесено за межі готовності DOM. У зафіксованому мобільному проході запит стартував на 1175 мс після domInteractive 1173 мс.
- Той самий Exo 2 підготовлено окремим UI-файлом: 91300 → 50176 байтів, приблизно −45%. Збережені українська абетка, Ґ/ґ, Є/є, І/і, Ї/ї, латиниця, пунктуація та змінна вага 400–900. Решта символів доступна через попередній повний файл; знак ₴ відсутній і в оригіналі та використовує системний fallback. Генератор: scripts/build-ui-font.py, потребує fonttools і підтримки Brotli.
- Прев’ю блогу отримало responsive srcset через власний loader: готові WebP віддаються напряму, без повторного Next image optimizer. На 390px / DPR 1 обрана ширина 420 замість єдиного великого зображення: 122868 → 30734 байти, приблизно −75%. Сервер приймає лише обмежений набір ширин; варіанти кешуються окремо та оновлюються з тегом blog-posts.
- Початковий JavaScript практично не змінився: близько 206 КБ переданих ресурсів у цьому тесті. Жодні функції чи аналітичні налаштування не вимикались.

## Порівняння

Chrome, 390/1440 × 900px, CPU ×4, затримка мережі 80 мс, 200000 байт/с завантаження. Три проходи на кожну ширину, щоразу новий контекст і вимкнений кеш браузера. Медіани нижче; серверні кеші між проходами не очищались, тож результати не характеризують гарантований холодний старт бази даних. Джерело: сусідній JSON з усіма проходами й ресурсами.

Обидва варіанти перевірені як production-компіляція webpack, `next build --experimental-build-mode compile`, потім `generate-env` і `next start`. Це не повний ISR-пререндер усіх маршрутів і не оцінка Lighthouse/PageSpeed. Зміни шрифтів/зображень і порядку CSS перевіряються тут без впливу dev-компіляції; швидкість кешованого HTML на сервері треба повторно виміряти після звичайної production-збірки й публікації.

| Метрика | 390px до → після | 1440px до → після |
| --- | ---: | ---: |
| TTFB | 49 → 43 мс | 20 → 31 мс |
| DOM interactive | 1428 → 1176 мс | 1435 → 1240 мс |
| DOMContentLoaded | 1428 → 1177 мс | 1435 → 1242 мс |
| FCP | 1588 → 1408 мс | 1612 → 1468 мс |
| LCP | 1588 → 1408 мс | 2712 → 2368 мс |
| CLS | 0,00654 → 0 | 0 → 0 |

Невеликі коливання локального TTFB — шум вимірювання; серверне прискорення не заявляється. DOMContentLoaded покращився приблизно на 18% на телефоні й 13% на комп’ютері. Зміни локальні й ще не впливають на показники живого сайту.

## Перевірки

- Production compile + generate-env; TypeScript та ESLint змінених TS/TSX.
- test-home-stylesheet-startup: запуск після DOM лише на головній, низький пріоритет, завершення readiness при load/error, звичайні стилі на інших маршрутах.
- test-home-critical-styles: затриманий повний CSS не ламає header/hero/blog на 390/1440px; геометрія стабільна після його надходження, немає зайвого preload чи горизонтального overflow.
- test-home-blog-cover, test-home-blog-cache, test-home-blog-first-paint: кешовані ширини, менша мобільна обкладинка, обробка збоїв і видимість тексту до картинки/API.
- test-home-priority-loading: перша обкладинка є в HTML, декодується, вікно входу відкривається на 390/1440px.
- Окремий browser smoke: головна 200 і невідомий маршрут 404, з JavaScript і без нього; 404 має оформлення, головна — справжній layout. Перевірено відкладений вибір авто та відповідь 400 на невалідну ширину прев’ю.
- У фінальних вимірюваннях та перевірках першого екрану помилок JavaScript не виявлено.
