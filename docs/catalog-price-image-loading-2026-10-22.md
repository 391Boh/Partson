# Завантаження цін і фотографій — 22.10.2026

Перевірено поточний код, локальний каталог у Chrome на ширині 390 px та регресійні сценарії. Реальний партнерський обліковий запис не використовувався; доступ до партнерських цін перевірено тестами маршруту.

## Ціни

Публічна ціна EUR вже приходить із товарами. Відображення UAH додатково чекає готовності курсу, визначення користувача та, для авторизованих, підтвердження відповідного цінового доступу. Партнерський запит потребує токена і серверної перевірки — цей бар’єр не знімався.

Виправлено зайвий таймер 220 мс перед запитом курсу. Data.tsx тепер використовує спільний loadEuroRate: одночасні споживачі мають один запит, кеш зберігається 30 хвилин. Прибрано дубльовані реалізації читання/запису кешу. Заблокований доступ до sessionStorage/localStorage більше не перешкоджає отриманню курсу через мережу.

У трьох dev-проходах перша ціна з’являлася приблизно за 2,72 / 5,25 / 5,89 с; перше фото — за 1,10 / 3,62 / 1,52 с. Запит курсу тривав 440 / 201 / 1679 мс. Це неоднакові серверні умови, зокрема після перебудови маршруту: прискорення всієї картки не підтверджено. Доведена зміна — усунення штучної паузи та дубльованих запитів між одночасними споживачами, не гарантована економія часу появи ціни.

## Зображення

Уже реалізовані пряме завантаження перших фотографій, preload першого екрана, пакетне прогрівання на сервері, дедуплікація, кеш, WebP-мініатюри до 480 px і резервний прямий запит через 1,4 с для наближених до екрана карток. У звичайному проході прогріті перші два зображення відповідали приблизно за 53–58 мс. Це не перевірка порожнього кешу 1С.

Перевірки пройшли: повільне фото відновлюється у фоні; остаточно відсутнє фото запам’ятовується; помилка під час очікування пакета відновлюється; пізній пакет не перезавантажує готове зображення; після переходу сторінки показуються нові фото. У цьому завданні механізм зображень не змінювався.

## Подальші покращення за пріоритетом

1. Передавати підтверджений актуальний курс із початковими даними каталогу або використовувати вже прогрітий серверний кеш. Холодне отримання курсу не повинно затримувати HTML. Потрібні ознака свіжості й збереження чинних правил округлення; випадковий курс підставляти не можна.
2. Заміряти окремо час отримання токена та захищених цін реального партнера. Наявність звичайної ціни не доводить готовність партнерської — усунення перевірки створить неправильне проміжне відображення.
3. Віддавати з 1С готові компактні мініатюри замість повнорозмірного base64 із подальшим зменшенням на вебсервері. Це потенціал для холодного кешу, а не підтверджений ефект поточних змін.
4. Не збільшувати одночасно кількість запитів фото й цін: вони використовують спільні ресурси 1С. Налаштовувати паралельність за заміром черги на холодному кеші.

Зміни не опубліковані.
