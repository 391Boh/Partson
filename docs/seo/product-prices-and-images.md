# Ціни та фото товарів у Google

Зміни 02–03.11.2026. Виправлення фіду опубліковане на сервері, погодинний
cron встановлений. Підсумок: [перевірка розгортання](../ops/merchant-feed-2026-11-03.md).

## Кількість товарів: виправлення ліміту 1000

02.11.2026 обидва живі XML-фіди містили рівно 1000 товарів. У локальній
конфігурації залишився `MERCHANT_FEED_MAX_ITEMS=1000`. Ручний генератор
знімає цей ліміт перед імпортом модуля, а HTTP-оновлення раніше
успадковувало його й перезаписувало спільний файл скороченим списком.
Фід включав і товари з нульовим залишком, тому відсутність залишків
не пояснює відсікання рівно на 1000 записах.

HTTP-маршрут тепер явно передає `maxItems: null`. Фільтри підтвердженого
фото та додатної публічної ціни збережені. Регресійний тест
`scripts/test-merchant-feed-refresh.mjs` використовує справжній генератор
XML з локальними тестовими даними: до виправлення виходило 1000 замість
1600; після виправлення всі 1600 залишаються і при початковій генерації,
і при оновленні старше години. Тест не звертається до 1С і не змінює
робочі знімки.

Виправлення розгорнуте в окремому production-релізі, локальний і серверний
ліміти вимкнені. Повна генерація з 1С 03.11.2026 повернула **1644 товари,
пропущено 0**. Обидві публічні адреси перевірені: 1617 товарів у наявності,
27 без залишку. Cron `17 * * * *` вказує на активний реліз. Фактична
кількість далі залежатиме від поточних даних 1С, фото й цін.

Старий `/merchant-feed.xml` тепер проксіюється на той самий Next.js
обробник, що й `/google-merchant-feed.xml`: обидві адреси мають однаковий
вміст та ETag. Прямий alias до XML-файлу прибирав актуалізацію ціни:
для одного перевіреного товару файл містив 386 грн, тоді як 1С і публічний
API вже повертали 178 грн. Кеш цієї товарної сторінки примусово оновлено;
після перевірки сторінка й обидві адреси фіду віддавали 178 грн.

## Узгоджена ціна

Сторінка товару, її Product/Offer, публічний API та Merchant-фід використовують звичайну ціну в EUR із пріоритетом збереженої правки товару. Приватні партнерські ціни не потрапляють у фід чи публічну розмітку. Видалена ціна не відновлюється зі старого знімка.

Фід зберігає EUR окремо від XML, перевіряє цілісність пари за SHA-256 та перераховує UAH за підтвердженим курсом. Вигаданий початковий курс 50 не використовується. За відсутності достовірних даних повертається тимчасовий 503 без кешування. Збережене джерело можна використати до 24 годин; після години маршрут намагається оновити його. Спільна генерація не запускає паралельні повні обходи каталогу.

Під час перевірки живого `tros-ruchn-halm-liv-audi-80-barab-ad030213` фід показував 359 грн, сторінка й API — 356 грн. Регресійний тест відтворює перерахунок 6,93 EUR × 51,37 → 356 грн, не змінюючи вартість доставки.

Підготовка фіду також атомарно оновлює товарні знімки. Процес перечитує їх раз на п’ять хвилин; сторінки мають revalidate 300 секунд. Sitemap lastmod враховує зміну ціни у гривні та URL галереї.

## Реальні зображення

Product, Open Graph і галерея використовують справжнє фото товару. Якщо основного фото немає, але є галерея, її перше зображення стає основним. Логотип магазину не видається за фото товару. Для основного фото доступні стабільні URL 1:1, 4:3, 16:9; пропорції зберігаються на білому фоні. Зміна вихідного фото одразу змінює кеш варіанта; ETag дозволяє 304. Тимчасовий збій 1С повертає 503, підтверджена відсутність — 404.

Фото перевіреного товару має лише 310 × 310 px. Варіанти зображень не створюють відсутніх деталей. Для кращого результату варто завантажувати чіткі оригінальні фото товарів вищої роздільності.

Google сам обирає вигляд результату й час переобходу. Розмітка та доступні фото підвищують придатність до розширених результатів, але не гарантують мініатюру: [Merchant listings](https://developers.google.com/search/docs/appearance/structured-data/merchant-listing), [Google Images](https://developers.google.com/search/docs/appearance/google-images), [відповідність ціни фіду сторінці](https://support.google.com/merchants/answer/6324371?hl=en).

## Під час публікації

1. У директорії активного релізу виконати `npm run generate:feed`: старий XML без EUR-метаданих потрібно замінити парою нових файлів.
2. Обидві адреси фіду мають проходити через Next.js-обробник `/google-merchant-feed.xml`. Приклад проксі для старої адреси є у `deployment/nginx/partson.conf`. Не замінювати його статичним alias до XML: тоді актуалізація ціни не виконується.
3. Перевстановити cron через `npm run merchant:cron:install`: новий типовий розклад `17 * * * *` замість щоденного. Перевірити абсолютний шлях активного релізу. Власний розклад задається `MERCHANT_FEED_CRON_SCHEDULE`.
4. Порівняти ціну одного товару у видимій сторінці, Product/Offer, API та фактичному URL фіду. Перевірити доступність фото і sitemap, Rich Results Test; у Search Console можна запросити повторну індексацію зміненого товару.

Перевірки: `scripts/test-product-google-pricing.mjs`, `scripts/test-product-seo-images.mjs`, `scripts/test-product-image-sitemap.mjs`, `scripts/test-product-image-final-miss.mjs` входять у `npm test` і не записують дані в живу 1С.
